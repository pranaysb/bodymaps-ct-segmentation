A lightweight, responsive web application for automated 3D abdominal organ segmentation on CT scans. Developed for the **Johns Hopkins University BodyMaps Developer Program** (Prof. Zongwei Zhou & Prof. Alan Yuille, CCVL Research Group).

Powered by **SuPreM** (*Supervised Pre-training for Medical image segmentation*, ICLR 2024 oral), pre-trained on 2,100 abdominal CT volumes from AbdomenAtlas.

---

## Honesty note (read this first)

An earlier version of this demo had two integrity bugs that are now fixed, and it's worth being upfront about them since this is going to the people who built the model:

1. **The inference endpoint was faked.** For the bundled demo case, `/api/case/{id}/infer` used to `sleep(0.5)` and return a hardcoded string: *"SuPreM benchmark inference verified. Mean Dice 0.927..."* — with no model ever running. It now always runs the real SuPreM UNet (sliding-window inference) on whatever compute device is available, and reports genuine elapsed time and device used. There is no simulated/instant mode left anywhere in the code.
2. **The Dice score was scoring predictions against themselves.** The app compared the predicted mask to a "ground truth" that was actually the same predicted array, which trivially always produces Dice = 1.0. The ground-truth segmentation shipped with the benchmark case is now stored in a separate, independent file (`labels_groundtruth.nii.gz`, never overwritten by inference) so Dice is computed between two genuinely different arrays.

The **Benchmark Validation** table below was regenerated from an actual executed run after fixing both issues (see the "How the benchmark numbers were produced" section for exactly how). A third, unrelated bug was also found and fixed in the process: the MONAI preprocessing pipeline (both here and in the Colab notebook) was missing `EnsureChannelFirstd`, which is required by MONAI ≥1.3 — without it, `sliding_window_inference` throws a shape error. That means this inference pipeline had never actually been run successfully end-to-end before this pass. It's fixed and verified working now.

## Key Features

- **Automated Multi-Organ Segmentation**: Predicts 9 primary abdominal structures (Liver, Spleen, Left & Right Kidneys, Pancreas, Stomach, Aorta, IVC, Gallbladder).
- **Interactive Multiplanar Radiology Viewer**:
  - Linked axial, coronal, and sagittal slice navigation via slider, keyboard arrows, or mouse wheel.
  - Hounsfield Unit (HU) window/level presets: **Abdomen** (W:400, L:40), **Soft Tissue** (W:350, L:50), **Bone** (W:1800, L:400), and **Lung** (W:1500, L:-600).
  - Color-coded organ overlays with individual visibility toggles and alpha opacity slider.
  - Real-time voxel statistics, physical volume in mL, and genuine Dice agreement scores (only shown when an independent ground truth exists for the case).
- **Real inference, run from the web app itself** — not just a notebook:
  - Clicking **"Run SuPreM Segmentation"** always executes the actual model. The app auto-detects and uses CUDA, then Apple Silicon (MPS), then falls back to CPU.
  - If only CPU is available, the app says so plainly and asks you to confirm before running (since it will be slow) — it never substitutes a fake or pre-baked result instead.
  - A companion Colab notebook (`bodymaps_colab_inference.ipynb`) runs the identical pipeline standalone on a free NVIDIA T4 GPU for a fast, independently reproducible run.
  - Custom CT upload support (`.nii.gz` / `.nii`), with basic validation (must be a real 3D volume of plausible size) and errors surfaced visibly rather than silently.
- **"How this works" panel in the UI** explaining exactly what's pre-loaded vs. live-computed, so a reviewer clicking around (not just reading code) can tell what's real.
- **NIfTI Export**: One-click download of multilabel segmentation mask (`.nii.gz`) or per-organ binary masks (`.zip`).

## Benchmark Validation on `BDMAP_00000338`

Generated by running the real `run_live_inference` pipeline (the exact code the "Run SuPreM Segmentation"
button calls) on **Apple Silicon GPU (Metal/MPS)**, on **2026-09-13**, taking **700.4 seconds** (~11.7 min).
Ground truth is the case's independently stored `labels_groundtruth.nii.gz` / `segmentations_groundtruth/`
files — never a copy of the prediction. These are the exact numbers the running app itself returns; verify
live at `GET /api/case/BDMAP_00000338/meta` (also shown in the sidebar's Accuracy panel and status ribbon).

| Organ | Label ID | Predicted (mL) | Ground Truth (mL) | Dice |
| :--- | :---: | :---: | :---: | :---: |
| **Liver** | 6 | 1616.3 | 1603.3 | **0.9831** |
| **Spleen** | 1 | 181.0 | 186.0 | **0.9722** |
| **Stomach** | 7 | 405.8 | 402.5 | **0.9679** |
| **Left Kidney** | 3 | 109.5 | 110.1 | **0.9492** |
| **Gallbladder** | 4 | 15.5 | 16.2 | **0.9203** |
| **Right Kidney** | 2 | 110.3 | 111.1 | **0.9240** |
| **Aorta** | 8 | 30.3 | 29.9 | **0.9019** |
| **IVC (Postcava)** | 9 | 43.8 | 46.8 | **0.8971** |
| **Pancreas** | 11 | 124.1 | 108.5 | **0.8548** |
| **Mean** | | | | **0.9301** |

A few honesty notes on this specific table:

- This machine has no CUDA GPU, so this run used Apple Silicon MPS acceleration rather than a T4 — still a
  real accelerator, just not the one referenced elsewhere in this README for the Colab path. The CPU-only
  path has not been separately timed after the `EnsureChannelFirstd` fix (this machine never falls back to
  plain CPU), so treat any CPU-only duration as an unverified estimate until someone actually measures it.
- **Per-organ Dice is scored from the single combined-label volume** (`combined_labels.nii.gz` vs.
  `labels_groundtruth.nii.gz`), not from the raw independent per-organ mask files. The raw per-organ ground
  truth annotations have ~1,800 voxels (out of ~1.5M organ voxels) claimed by more than one organ at shared
  boundaries (e.g. liver/gallbladder) — an expected artifact of independently annotated organ masks. Merging
  them into one label per voxel resolves those overlaps, so scoring against the merged file (what the app
  actually displays and exports) gives numbers a few thousandths off from scoring against the raw per-organ
  files directly. Both are legitimate; the app is internally consistent about which one it uses everywhere.
- Coincidentally, this real mean Dice (0.9301) lands close to the fabricated 0.927 figure the earlier,
  dishonest version of this app hardcoded — but that number was never computed and was wrong to state as
  fact regardless of how close it happened to land. This table is what replaced it.

## Local Setup & Quick Start

### 1. Clone the SuPreM model repository

Not vendored in this repo (it's a separate ~300MB third-party codebase with its own license). The app expects it at the project root:

```bash
git clone https://github.com/MrGiovanni/SuPreM.git
```

### 2. Create Environment & Install Dependencies
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Download the model checkpoint

Not included in this repo (233 MB). Download it before running inference:

```bash
mkdir -p SuPreM/direct_inference/pretrained_checkpoints
wget -O SuPreM/direct_inference/pretrained_checkpoints/supervised_suprem_unet_2100.pth \
  https://huggingface.co/MrGiovanni/SuPreM/resolve/main/supervised_suprem_unet_2100.pth
```

If it's missing, `/api/health` reports `checkpoint_exists: false` and the app surfaces a clear error rather than failing silently when you try to run inference.

### 4. Launch the Web Application
```bash
uvicorn app:app --port 8000 --reload
```

Open your browser at **[http://localhost:8000](http://localhost:8000)**.
- The bundled benchmark scan `BDMAP_00000338` loads automatically, showing whatever prediction (if any) was last computed for it, honestly labeled with when and on what hardware.
- The hardware badge in the header always shows the real compute device this server detected (CUDA GPU, Apple Silicon MPS, or CPU-only).
- Click **⚡ Run SuPreM Segmentation** to run the actual model. On CPU-only machines you'll be asked to confirm first, since it will be slow.
- Use arrow keys, mouse wheel, or the slider to explore all axial/coronal/sagittal slices.
- Click **ⓘ How this works** in the header for an in-app explanation of what's live-computed vs. pre-loaded.

## Running Live GPU Inference on Google Colab

For a fast, independently reproducible run (and to cross-check the numbers below on different hardware):

1. Upload or open [`bodymaps_colab_inference.ipynb`](bodymaps_colab_inference.ipynb) in **[Google Colab](https://colab.research.google.com/)**.
2. Select **Runtime > Change runtime type > T4 GPU**.
3. Run all cells:
   - Verifies the NVIDIA T4 GPU via `nvidia-smi`.
   - Downloads model weights and the benchmark dataset.
   - Executes live sliding-window inference.
   - Computes quantitative Dice agreement against ground truth.
   - Plots axial slices with colored organ overlays.

This notebook uses the exact same model, checkpoint, and preprocessing pipeline as the web app — the numbers it produces are directly comparable, not a separate "for show" path.

## API Documentation

FastAPI provides an automatic interactive Swagger UI at **`http://localhost:8000/docs`**.

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/health` | Real hardware detection (CUDA/MPS/CPU) and checkpoint status |
| `GET` | `/api/cases` | List of available CT scan cases |
| `GET` | `/api/case/{case_id}/meta` | Geometry, HU stats, organ metrics, and inference provenance |
| `GET` | `/api/case/{case_id}/slice/{idx}` | Rendered 2D slice PNG with windowing and overlays |
| `POST` | `/api/upload` | Upload new `.nii.gz` CT volume (validated as a real 3D volume) |
| `POST` | `/api/case/{case_id}/infer` | Run real SuPreM 3D segmentation (`?confirm_slow=true` to proceed on CPU) |
| `GET` | `/api/case/{case_id}/download/{fmt}` | Download segmentation results (`nii` or `zip`) |

### Error handling

- Missing checkpoint file → `500` with the exact path expected and a download link, both from `/api/case/{id}/infer` and surfaced as a UI banner (not a silent failure).
- Invalid/non-3D upload → `400` with the actual detected shape/dimensionality.
- Inference failing partway through → results are staged in a temp directory and only swapped into place atomically on full success, so a crash mid-run never corrupts a case's existing prediction; the error is returned to the UI, not swallowed.

## How the benchmark numbers were produced

The table above was generated by running the real `run_live_inference` pipeline (the same code path the "Run SuPreM Segmentation" button calls) against the bundled `BDMAP_00000338` case, then computing Dice between the resulting prediction and the independently stored `segmentations_groundtruth/` files — never against a copy of the prediction itself. See the exact device, wall-clock time, and timestamp noted with the table.
